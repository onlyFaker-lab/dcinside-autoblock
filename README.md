# 디시 자동 갱신차단 (크롬 확장)

차단이 만료된 악성 유저를 감지해 31일 재차단합니다.
마이너 갤러리 매니저(주딱) · 부매니저(파딱)용.

파이썬 버전과 하는 일은 같지만, 브라우저에 이미 로그인된 세션을 쓰기 때문에
아이디와 비밀번호를 어디에도 저장하지 않습니다.

> 크롬을 처음 다뤄보신다면 `설치법.txt` 를 보세요. 그림 없이 순서대로만 적어뒀습니다.

## 받기

오른쪽 위 초록색 `Code` 버튼 → `Download ZIP` 으로 받은 뒤 압축을 푸세요.

## 설치

1. 크롬 주소창에 `chrome://extensions` 입력
2. 오른쪽 위 **개발자 모드** 켜기
3. 왼쪽 위 **압축해제된 확장 프로그램을 로드합니다** 클릭
4. 이 폴더 선택

주소창 오른쪽 퍼즐 아이콘에서 이 확장을 고정해두면 편합니다.

## 처음 설정

확장 아이콘을 누르고 **설정** 탭에서 갤러리 ID를 입력한 뒤 저장하세요.
갤러리 주소 `gall.dcinside.com/mgallery/board/lists/?id=여기` 의 `여기` 부분입니다.

그 다음 **영구 관리 명단** 탭에서 재차단할 식별코드를 추가합니다.
차단 목록 화면 괄호 안에 보이는 값입니다. (`ㅇㅇ (abcd1234)` → `abcd1234`)

## 동작

설정한 시각(기본 09:30, 21:30)에 명단에 있는 사람을 하나씩 조회합니다.
차단이 풀린 사람이 있으면 **재차단 후보** 탭에 띄우고 멈춥니다.
`재차단 실행`을 눌러야 실제로 차단됩니다.

**크롬이 켜져 있어야 동작합니다.** 파이썬 버전과 다른 점입니다.
크롬이 꺼져 있던 시간의 예정 확인은 소급 실행하지 않습니다.

## 알아둘 것

**IP는 자동 갱신하지 않습니다.** 디시는 완장에게도 IP 앞 두 자리까지만 보여줍니다.
그 상태로 차단하면 통신사 대역을 통째로 막는 셈인데, 정작 상대는 IP를 바꾸면 그만이고
무고한 갤러만 막힙니다. 명단에 IP를 넣으려 하면 막습니다.

**재차단하면 항상 코드 단독 차단이 됩니다.** 원래 `+ IP`로 걸려 있던 사람도 마찬가지입니다.
디시의 직접 차단 기능이 식별코드만 받기 때문입니다.

**차단 결과를 검증합니다.** 서버가 성공이라고 응답해도 믿지 않고,
목록을 다시 읽어 31일 차단이 실제로 걸린 것만 성공으로 기록합니다.

**완장이 직접 풀어준 사람은 재차단하지 않습니다.** 신문고 민원 등으로 차단을
풀어준 경우, 기간이 남았는데 해제된 상태가 됩니다. 자연 만료와 구분해서
재차단 대신 따로 알려주고, 명단에서 뺄 수 있게 합니다.

## 명단 채우기

분탕이 많은 갤러리에서 식별코드를 하나씩 옮겨적는 건 무리입니다.
`명단 채우기` 탭에서 `31일 차단 불러오기` 를 누르면 차단 목록을 훑어
31일 차단을 걸었던 사람을 모아옵니다. 체크해서 한 번에 명단에 담을 수 있습니다.

이미 명단에 있는 사람과 IP 차단은 빼고 보여줍니다.
재차단 사유는 원래 걸었던 사유를 그대로 씁니다.

**어디까지 훑을지는 날짜로 정하는 편이 낫습니다.** `이 날짜까지` 에 날짜를
넣으면 그보다 오래된 차단이 나오는 순간 멈춥니다. 페이지 수를 감으로 찍을
필요가 없고, 필요 이상으로 훑지도 않습니다.

날짜를 넣으면 페이지 입력란은 흐려집니다. 날짜가 기준이고, 페이지 수는
안전장치(3000페이지, 90,000행)로만 남습니다. 날짜에 닿기 전에 그 상한에
걸리면 기록에 "가장 오래된 행이 언제였는지"가 남습니다.

한 페이지가 30행이고 요청 간격이 0.3초(1000페이지 초과 시 0.5초)라,
1000페이지면 대략 10~15분 걸립니다.

불러온 목록 위에 **사유 칩**이 나옵니다. 사유를 골라 그 사유로 차단했던 사람만
추릴 수 있습니다. 예를 들어 `광고`만 켜두면 광고로 차단했던 사람만 보이고,
`보이는 사람 전체 선택`을 누르면 그 사람들만 담깁니다.
`전체` 를 누르면 필터가 풀립니다.

날짜를 비워두면 페이지 수가 기준이 됩니다. 기본은 최근 10페이지입니다.

## 명단이 많을 때

명단이 수만 명이 되어도 견디도록 만들었습니다.

**만료가 임박한 사람만 조회합니다.** 31일 차단 중인 사람은 그동안 상태가 바뀌지
않으므로 만료 예정 시각까지 아예 건드리지 않습니다. 목록에 숨어 있는 처리 시각을
읽어 만료 시점을 계산해두고, 그때가 되면 확인합니다.

그래서 실제 조회량은 명단 크기가 아니라 그날 만료되는 인원에 비례합니다.

| 명단 | 하루 조회 |
|---|---|
| 1,000명 | 약 30회 |
| 10,000명 | 약 320회 |
| 100,000명 | 약 3,200회 |

한 번에 조회할 인원에 상한(기본 300명)이 있어 몰려도 나눠서 처리합니다.
설정 탭에서 `한 번에 조회할 최대 인원` 으로 조절할 수 있습니다.

**기록이 어긋날 수 있습니다.** 만료 예정 시각을 미리 계산해두는 방식이라,
그 전에 완장이 손으로 차단을 풀면 다음 만료 때까지 모르고 지나갑니다.
그래서 매 확인마다 오래 확인하지 않은 사람을 몇 명씩 섞어서 봅니다.
(설정 탭의 `매번 섞어서 볼 점검 인원`, 기본 20명)
바로 반영하고 싶으면 명단 탭의 `전체 다시 확인` 을 누르세요.

**오래 안 보이는 사람은 자동으로 쉽니다.** 해제된 목록은 30일만 보관되므로,
기록이 사라진 뒤에는 조회해도 알 수 있는 게 없습니다. 60일간 기록이 없으면
자동으로 중지 처리하고 알려줍니다. 지워지지는 않으니 필요하면 다시 켜면 됩니다.

**재차단은 묶어서 보냅니다.** 디시 입력 제한(500자)에 맞춰 자동으로 나누므로
인원이 많아도 누락되지 않습니다.

명단 탭에는 검색창이 있고 한 번에 200명씩 보여줍니다.

## 안전장치

- 후보를 찾아도 자동으로 차단하지 않음. 사용자가 버튼을 눌러야 실행
- 명단에 등록된 대상만 갱신. 만료된 차단을 전부 자동 갱신하지 않음
- 이미 차단 중인 대상은 후보에서 제외 (중복 차단 방지)
- 한 번에 100건 초과면 실행하지 않고 중단 (설정에서 조절)
- 조회는 하루 1~2회. 짧은 주기로 서버를 긁지 않음
- 재차단 이력을 남겨 사후 추적 가능

## 권한을 왜 받나

| 권한 | 쓰임 |
|---|---|
| `gall.dcinside.com` | 차단 목록 조회와 차단 실행 |
| `cookies` | 디시가 요구하는 인증 토큰(`ci_c`)을 읽기 위해 |
| `storage` | 명단·설정·이력 저장 (전부 내 컴퓨터 안에만) |
| `alarms` | 정해진 시각에 확인 |
| `notifications` | 후보를 찾았을 때 알림 |

외부로 데이터를 보내지 않습니다. 디시 외의 사이트에는 접근하지 않습니다.

## 파일

```
manifest.json   확장 설정
background.js   정기 확인, 재차단 실행
dc.js           디시 조회·차단 API, HTML 파싱
popup.html/css/js   화면
test.mjs        파싱·판정 검사 (node test.mjs)
test-popup.mjs  화면 동작 검사 (node test-popup.mjs)
```

### 1.6.2
- 하루 차단 한도 문구를 실제로 확인해 반영했습니다. 한도에 걸리면 1시간·6시간

- **갤로그 점검이 글·댓글 수도 같이 기록합니다.** 다음 점검 때와 비교해 숫자가
  그대로면 그동안 디시에서 아무것도 안 한 것입니다. 지금까지의 활동 점검은
  해당 갤에 쓴 글만 봐서 댓글로만 노는 사람을 못 잡았는데, 그 구멍이 막힙니다.
  요청은 늘지 않습니다. 이미 열고 있던 페이지에서 숫자만 더 읽습니다.
- 비공개 갤로그도 개수는 보이므로 공개 여부와 무관하게 동작합니다.
- **첫 점검에서는 아무것도 나오지 않습니다.** 비교할 이전 숫자가 없기 때문입니다.
  한 번 더 돌려야 뜻이 생깁니다.

### 1.6.1
- **명단 채우기에서 날짜를 넣으면 날짜가 기준이 됩니다.** 전에는 페이지
  수(기본 10)가 먼저 걸려서, 날짜를 넣어도 10페이지에서 멈췄습니다.
- **명단 내보내기에 메모와 사용 여부가 들어갑니다.** 확장을 다시 깔아도
  메모가 그대로 살아납니다. 남에게 넘기는 후보 파일은 전처럼 코드와 사유만
  담습니다.
- 파일에 모르는 사유가 있으면 조용히 바꾸지 않고 몇 명인지 알려줍니다.
- 명단 정리 표의 머리글 체크박스가 동작합니다. 넣어만 두고 기능을 붙이지
  않아서 눌러도 아무 일이 없었습니다.

### 1.6.0
- **명단 정리 탭을 추가했습니다.** 명단에서 뺄 만한 사람을 찾습니다.
  자동으로 지우지 않고, 확인 후 직접 지웁니다.
- **활동 점검** — 갤 글 목록을 훑어 최근에 글을 쓴 식별 코드를 모읍니다.
  글 목록의 글쓴이 칸에 식별 코드가 들어 있어서, 명단이 몇 명이든
  요청 수가 같습니다. 3개월 기준으로 하루 100글 갤러리면 94페이지입니다.
- **갤로그 점검** — 탈퇴한 계정을 찾고, 글·댓글 수를 기록합니다. 한 명당 요청 한 번이라 느립니다.
  활동 점검으로 명단을 한 번 걸러낸 뒤에 돌리는 게 좋습니다.
- 갤로그를 보기 위해 `gallog.dcinside.com` 권한이 추가됐습니다.

### 1.5.8
- **명단 채우기에 `이 날짜까지` 를 넣었습니다.** 페이지 수를 감으로 찍지 않아도
  됩니다. 그 날짜보다 오래된 차단이 나오면 거기서 멈춥니다.
- **페이지 상한을 3000으로 올렸습니다.** 최대 90,000행입니다.
  1000페이지가 넘으면 요청 간격을 500ms로 넓힙니다.
- 수천 페이지를 훑어도 메모리가 늘지 않게 고쳤습니다. 예전에는 본 행을 전부
  기억했는데, 직전 페이지만 있으면 충분합니다.

### 1.5.7
- **명단 채우기 페이지 상한을 100 → 500으로 올렸습니다.** 한 페이지가 30행이니
  최대 15,000행까지 훑습니다. 수백 페이지는 몇 분 걸리며, 도는 동안 다시 누르면
  막습니다.
- **하루 차단 한도를 알아챕니다.** 디시는 완장 계정마다 하루 차단 횟수를
  제한합니다. 한도에 걸리면 남은 요청을 보내지 않고 멈추며, 못 보낸 사람은
  후보 목록에 그대로 남겨 다음에 이어서 할 수 있습니다.
  보내지도 않은 사람을 '실패'로 기록하지 않습니다.
- **후보 탭에 `남은 후보 복사`를 넣었습니다.** 사유별로 정리된 코드 목록이
  복사됩니다. 갤러리에 그대로 올리면 다른 완장이 이어서 차단할 수 있습니다.
  닉네임이나 메모는 넣지 않습니다.
- **명단 탭에 `여러 명 한 번에`를 넣었습니다.** 갤러리에 올라온 글을 통째로
  붙여넣어도 코드만 골라냅니다.

### 1.5.6
- 동작에는 변화가 없습니다. 코드 정리와 테스트 보강입니다.
- `isBusy` / `localDateKey` / 검증 페이지 수 계산이 `dc.js`와 `background.js`에

  고쳤을 때 테스트가 눈치채지 못합니다.
- `test.mjs`를 실제 관리 화면 마크업으로 다시 썼습니다. 예전 픽스처는 지어낸
  구조라 통과해도 실제 동작을 보장하지 못했습니다. 페이지 순회 검사도 넣었습니다.

### 1.5.5
- **명단 채우기에 사유 필터를 추가했습니다.** 불러온 뒤 사유 칩을 눌러
  그 사유로 차단했던 사람만 추릴 수 있습니다. 사유별 인원이 함께 표시되고,
  `보이는 사람 전체 선택`은 걸러낸 사람에게만 적용됩니다.
  (파딱 요청 반영)
- 명단에 담기 전 확인창에 사유별 인원을 보여줍니다.
- 아무도 선택되지 않으면 `명단에 추가` 버튼이 눌리지 않습니다.

### 1.5.4
- **명단 채우기가 1페이지만 불러오던 문제 수정.** 페이지 넘김을 화면의 페이저
  링크에서 읽어오다가, 페이지 위쪽 즐겨찾기 레이어의 페이저를 먼저 잡아
  링크를 하나도 못 찾고 있었습니다. 이제 링크를 보지 않고 페이지 번호를
  직접 올리며 읽고, 끝은 내용으로 판단합니다.
- 페이지 넘김이 실제로 됐는지 기록 창에 남깁니다.
  (`N페이지에서 차단 이력 M행을 읽었습니다`)
- 재차단 검증 시 훑을 페이지 수를 실제 페이지 크기(30행)에 맞춰 계산합니다.

  '이력 없음'과 구분되지 않아, 아무도 재차단되지 않는데도 조용히 넘어갔습니다.
- 차단/해제 상태를 읽지 못한 행도 파싱 실패로 셉니다.
- 사유 표기의 공백 차이를 흡수합니다. (`혐오콘텐츠` → `혐오 콘텐츠`)
- 긴 조회 도중 작업 표시가 만료돼 실행이 겹치던 문제 수정.

### 1.5.2
- 서비스워커가 작업 도중 종료되면 '작업 중' 표시가 남아 확장이 조용히
  멈추던 문제 수정. 30분이 지난 표시는 무시하고, 브라우저 재시작 시 풉니다.
- 설정을 저장할 때 화면에 없던 항목이 지워지던 문제 수정.
  조회 인원과 점검 인원을 설정 탭에서 조절할 수 있습니다.
- 디시가 표 마크업에 속성을 덧붙여도 견디도록 파싱을 넓혔습니다.
- 재차단 검증에서 못 찾은 대상을 상한 없이 전부 개별 확인합니다.
  예전에는 20건을 넘으면 확인 없이 실패로 기록했습니다.

## 명단 정리

명단이 커지면 이미 떠난 사람이 계속 남습니다. 두 가지로 걸러냅니다.

**활동 점검**은 갤 글 목록을 훑습니다. 글 목록의 글쓴이 칸에 식별 코드가
들어 있어서, 한 번 훑으면 명단 전원의 활동 여부를 동시에 알 수 있습니다.
사람마다 조회하는 방식이 아니라 명단이 커져도 요청이 늘지 않습니다.

**갤로그 점검**은 탈퇴한 계정을 찾습니다. 갤로그 주소가
`gallog.dcinside.com/_error/deleted` 로 넘어가면 탈퇴입니다.
한 명당 요청 한 번이라 느리니, 활동 점검을 먼저 돌려 대상을 줄이세요.

결과는 근거가 확실한 순서로 보여줍니다.

| 표시 | 뜻 | 근거 |
|---|---|---|
| 탈퇴 | 갤로그가 삭제됨 | 확실 |
| 코드 확인 필요 | 갤로그가 404 | 코드를 잘못 읽었을 수 있음. 지우지 말고 확인 |
| 글 없음 | 목록에 안 나옴 | 약함. 댓글만 다는 사람도 여기 걸림 |

**어느 쪽도 자동으로 지우지 않습니다.** 글 목록에는 댓글이 나오지 않아서,
댓글로만 활동하는 사람이 '글 없음'으로 잡힙니다. 지우기 전 확인창에서
그런 사람이 몇 명 섞여 있는지 알려줍니다.

비공개 갤로그와 디시가 차단한 갤로그는 '정상'으로 분류돼 명단에 남습니다.
못 알아본 것을 지우는 것보다 남기는 편이 안전합니다.

## 완장끼리 후보 나누기

디시는 완장 계정마다 하루 차단 횟수를 제한합니다. 매니저도 걸립니다.
후보가 그보다 많으면 한도에 걸린 시점에서 멈추고, 못 보낸 사람은
**후보 목록에 그대로 남습니다.** 시도조차 안 한 사람을 실패로 적지 않습니다.

한도에 걸려도 1시간·6시간 차단은 됩니다. 막히는 건 하루 이상짜리뿐입니다.
당장 막아야 할 사람이 있으면 관리 화면에서 짧게 걸어두고 내일 다시 실행하세요.

후보 탭의 `남은 후보 복사`를 누르면 이런 형태로 복사됩니다.

```
# 재차단 후보 3명 (2026-09-07)

# 음란성 2명
aaa0001
aaa0002

# 광고 1명
bbb0001
```

이걸 갤러리에 올리면 다른 완장이 이어서 처리할 수 있습니다. 받는 쪽은
디시 직접 차단 창에 붙여넣어도 되고, 명단 탭의 `여러 명 한 번에`에
글 전체를 그대로 붙여넣어도 됩니다. 코드만 골라냅니다.

### 파일로 주고받기

용도가 둘이라 담기는 내용이 다릅니다.

**후보 내보내기** (후보 탭) — 남에게 넘기는 용도입니다. **식별 코드와 사유만**
들어갑니다. 닉네임과 메모는 넣지 않습니다. 갤러리에 올려도 됩니다.

**명단 내보내기** (명단 탭) — 내 백업 용도입니다. 사유와 **메모, 사용 여부까지**
같이 들어갑니다. 브라우저를 옮기거나 확장을 다시 깔았을 때 그대로 되살아납니다.
메모가 들어 있으니 공개된 곳에는 올리지 마세요. 내보낼 때 한 번 물어봅니다.

받는 쪽은 명단 탭 → `여러 명 한 번에` → `파일 불러오기` 입니다.
다른 갤러리에서 내보낸 파일이면 가져오기 전에 알려줍니다.
이 확장이 만든 파일이 아니어도, 코드 목록이 든 텍스트 파일이면 코드만 골라냅니다.

파일에 우리가 모르는 사유가 들어 있으면 `음란성` 으로 넣되, 몇 명이 그렇게
됐는지 가져오기 전에 알려줍니다.

디시 게시글에는 파일을 첨부할 수 없습니다. 갤러리에 공개로 올릴 때는
`남은 후보 복사` 를, 완장끼리 직접 주고받을 때는 파일을 쓰세요.

차단 목록을 비공개로 두는 갤러리라면 코드를 공개 게시물에 올리는 것이
적절한지 완장단에서 먼저 정하세요.
